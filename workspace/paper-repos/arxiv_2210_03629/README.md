## What this paper does

ReAct is a prompting technique for large language models that interleaves
free-form natural-language **"thoughts"** with task-specific **"actions"**
when solving a task. Reasoning helps the model plan, track progress, and
recover from mistakes; acting lets the model pull in fresh information from
an external source (a Wikipedia API, a simulated household, a shopping
website) instead of relying only on its frozen internal knowledge. On
question answering (HotpotQA) and fact verification (FEVER), ReAct reduces
hallucination compared to chain-of-thought prompting by grounding reasoning
in retrieved evidence. On interactive decision-making benchmarks (ALFWorld,
WebShop), ReAct substantially outperforms action-only and imitation-learning
baselines using just one or two in-context examples.

**Important:** ReAct is a *prompting/orchestration paradigm* applied to a
frozen LLM (PaLM-540B in the paper), not a novel trainable neural network.
This repo is therefore structured as an LLM-agnostic **agent framework**
(`src/react_agent/`) rather than a model-training repo — see
"Reproducibility Notes" below.

## Quick Start

```bash
# 1. Clone and enter the repo
cd paper-repos/arxiv_2210_03629

# 2. Install dependencies
pip install -r requirements.txt
pip install -e .

# 3. Set your LLM API key (PaLM-540B is not public; see Reproducibility Notes)
cp .env.example .env
# edit .env and set DEEPSEEK_API_KEY=...  (get one at https://platform.deepseek.com/)
# (to use OpenAI instead, set model.provider: openai in configs/config.yaml and
# set OPENAI_API_KEY in .env instead)

# 4. Download the automatable datasets
python data/download.py --dataset hotpotqa
python data/download.py --dataset fever
# (ALFWorld / WebShop require separate setup -- see data/README_data.md)

# 5. Run a single ReAct episode
python inference.py --task hotpotqa --input "What profession do Nicholas Ray and Elia Kazan have in common?" --config configs/config.yaml
```

## Training

The paper's headline results require **no training** — they are pure
few-shot prompting. `train.py` only reproduces the *optional* Appendix B.1
finetuning ablation (bootstrapping 3,000 ReAct-generated trajectories to
finetune a smaller substitute model):

```bash
python train.py \
  --method react \
  --model-size 8b \
  --hf-model-name-or-path <a-hf-causal-lm> \
  --trajectories-path results/bootstrapped_trajectories.json \
  --output-dir checkpoints/react-8b-ft \
  --config configs/config.yaml
```

Supports `--resume <checkpoint>`, `--seed <int>`, `--debug` (tiny run for a
smoke test), and `--dry-run` (build everything, skip actual training).

## Evaluation

Reproduces Table 1 (HotpotQA/FEVER), Table 3 (ALFWorld), Table 4 (WebShop):

```bash
# HotpotQA, ReAct method
python evaluate.py --task hotpotqa --method react --config configs/config.yaml --output-dir results/hotpotqa_react

# FEVER, ReAct -> CoT-SC backoff
python evaluate.py --task fever --method react_cotsc --config configs/config.yaml --output-dir results/fever_react_cotsc

# ALFWorld (requires `pip install alfworld && alfworld-download` first)
python evaluate.py --task alfworld --method react --config configs/config.yaml --output-dir results/alfworld_react

# Quick local smoke test on a handful of examples
python evaluate.py --task hotpotqa --method react --debug
```

`--method` options: `standard`, `cot`, `cot_sc`, `act`, `react`, `react_im`
(ALFWorld only), `cotsc_react` (CoT-SC → ReAct backoff), `react_cotsc`
(ReAct → CoT-SC backoff).

## Reproducibility Notes

This section documents every known deviation from the paper and every
low-confidence implementation choice. See
`sir-registry/arxiv_2210_03629/sir.json` (`implementation_assumptions`,
`ambiguities`) and `architecture_plan.json` (`risk_assessment`) for full
provenance.

- **Base model substitution (High risk).** PaLM-540B is not publicly
  accessible. `configs/config.yaml::model` defaults to DeepSeek's API
  (`deepseek-chat`, itself an assumed substitute) via
  `src/react_agent/llm/llm_client.py::OpenAIClient`, which is built on the
  `openai` Python SDK pointed at an OpenAI-API-compatible `base_url` — this
  works for DeepSeek, OpenAI, and other compatible providers without
  needing a separate SDK per provider. Set `model.provider: openai` (and
  `OPENAI_API_KEY` in `.env`) to switch to OpenAI itself instead. The
  paper's own Appendix A.1 similarly substitutes GPT-3 `text-davinci-002`
  and reports it *outperforms* PaLM-540B — so exact score parity should not
  be expected regardless of backend; compare relative trends between
  methods instead. An `HFLocalClient` backend is also provided for
  local/open-weight models (needed for evaluating the optional finetuning
  path).

- **Few-shot exemplar prompts (High risk).** The paper's full Appendix C
  prompts (6 exemplars for HotpotQA, 3 for FEVER, 3-per-task-type × 6
  permutations for ALFWorld) were not present in the parsed PDF text.
  `src/react_agent/prompts/prompt_templates.py` hand-authors exemplars from
  the illustrative fragments in Figure 1 and Tables 6-9, following the
  documented thought taxonomy. **Verify/replace these against the official
  repo (https://react-lm.github.io/) before trusting absolute score
  comparisons** — every affected function is marked with a `# TODO: verify
  against paper Appendix C` comment.

- **Finetuning hyperparameters (Medium risk).** Appendix B.1 states batch
  size 64 and per-(method, model-size) step counts, but no optimizer,
  learning rate, or LR schedule. `configs/config.yaml::training` marks these
  fields `# ASSUMED` (AdamW, lr=1e-5, linear warmup+decay) — tune before
  relying on finetuning results.

- **WebShop Score normalization (Medium risk).** The paper describes Score
  as "percentage of desired attributes covered ... averaged across all
  episodes" without an exact per-episode formula.
  `evaluation/metrics.py::MetricsCalculator.webshop_score` assumes
  `|matched| / |requested|`; cross-check against the official WebShop repo
  (Yao et al., 2022) scoring function.

- **ALFWorld / WebShop external dependencies (Medium risk).** Both require
  separate, non-pip-installable setup (ALFWorld game assets via
  `alfworld-download`; a running WebShop Flask server). See
  `data/README_data.md`. HotpotQA/FEVER evaluation runs fine without either
  installed.

- **Wikipedia search "similar entities" fallback (Low risk).** The exact
  algorithm behind `search[entity]`'s top-5-similar-entity suggestion is not
  specified; `envs/wikipedia_env.py` uses the `wikipedia` package's built-in
  search-suggest as a reasonable stand-in.

- **Step-cap counting convention (Low risk).** The ReAct↔CoT-SC backoff step
  caps (7 for HotpotQA, 5 for FEVER) are implemented as counting only
  (action, observation) pairs, not intervening Thoughts — see
  `TrajectoryContext.n_env_steps()` and
  `configs/config.yaml::evaluation.step_counting_mode`.

- **Evaluation metric normalization (Medium confidence).** HotpotQA EM uses
  a standard lowercase/article/punctuation-stripping normalization, matching
  common SQuAD/HotpotQA convention; this exact normalization function is not
  restated in the parsed paper text.
